# NetDash vs IPAM 솔루션 — 비교·SWOT 분석 (2026-07-11, v3.71.0 기준)

## 0. 전제: NetDash의 포지션

NetDash는 순수 IPAM(IP Address Management)이 아니라 **"실측 기반 폐쇄망 네트워크 현황판 + 감사 도구"**다.
IPAM의 핵심(서브넷 계획·IP 할당 대장·DNS/DHCP 연동)과 겹치는 부분은 일부이며,
IPAM이 못 하는 것(장비 실측 수집, 장부 대조, 토폴로지, 설비 위치 추적)을 주력으로 한다.
따라서 비교는 "대체재"가 아니라 **"폐쇄망 환경에서 어느 쪽이 실제 문제를 해결하나"** 관점으로 수행.

## 2. SWOT

### Strengths (강점)
1. **실측 데이터 우위**: IPAM 대부분은 "사람이 입력한 값"을 관리(NetBox는 아예 SSoT 철학으로 스캔 거부). NetDash는 스위치/방화벽에서 MAC·ARP·포트·config를 직접 수집 → **문서와 현실의 괴리를 없애는 것 자체가 제품**. 장부 대조(reconcile)는 조사 범위 내 어떤 IPAM에도 없는 기능.
2. **폐쇄망 최적 배포**: 단일 exe, DB 파일 하나, 무설치, 오프라인 완결. NetBox(PostgreSQL+Redis+Python), phpIPAM(LAMP)은 폐쇄망 반입·유지가 부담. DPAPI 자격증명 암호화도 Windows 네이티브.
3. **멀티벤더 실수집 검증**: Cisco IOS/IOS-XE/NX-OS, Arista, Extreme EXOS, Alteon(메뉴 CLI), PAN-OS, FortiGate — 레거시 장비(SHA1 KEX 등)까지 커버. 상용 도구도 Alteon 같은 구형은 잘 지원 안 함.
4. **감사 특화**: 감사로그, config diff 알람, 한국어 엑셀 보고서 — 대상 사용자(IT 감사자·보안팀)에 직결.
5. **운영 알람**: 도달성 감시, 신규/오프라인/이동 감지, flap/loop 로그 분석, 이메일 통보 — 경량 NMS 역할 겸업.

### Weaknesses (약점)
1. **IPAM 코어 부재**: 서브넷 계획·IP 할당/예약 대장·사용률 추적이 없음. "이 대역에서 빈 IP 주세요" 워크플로 불가 → IPAM 대체재로는 못 씀. (관측된 IP만 알고, 계획된 IP는 모름)
2. **단일 사용자 모델**: 토큰 1개, RBAC 없음. 감사자·운영자·열람자 분리 불가 — 조직 확산 시 병목.
3. **IPv4 전용**: IPv6 파싱/검색/토폴로지 미지원.
4. **SQLite 단일 파일**: 동시 쓰기 규모 한계, HA 불가. 수십만 엔드포인트급 확장 시 재설계 필요.
5. **1인 개발 지속성**: 상용/커뮤니티 대비 버스 팩터 1. 테스트 539개가 방어선.
6. **API 비공개/문서 부재**: 외부 자동화 연계(NetBox처럼 IaC 소스로 쓰기)가 어려움.

### Opportunities (기회)
1. **IPAM-lite 모듈 추가**: 이미 가진 실측 ARP/MAC/설비 데이터에 "서브넷 정의 + 할당 대장 + 사용률(실측 대비)"만 얹으면 **'계획 vs 실측' 겸비 IPAM**이 됨 — NetBox(계획만)·스캐너(실측만)의 틈새. 기존 reconcile 엔진 재사용 가능.
2. **폐쇄망 시장 틈새**: 금융·공공·제조 폐쇄망은 클라우드 IPAM(Infoblox SaaS 등) 도입 불가 — 오프라인 단일 exe는 구조적 우위.
3. **NetBox 공존 전략**: 경쟁 대신 "NetBox의 실측 검증 피더" 포지션(내보내기/대조) — 이미 장부 대조 프레임이 있어 저비용.
4. **컴플라이언스 확장**: PRD 원안(NIST/PCI-DSS 기준 SSH·방화벽 감사 + remediation)을 복원하면 감사 도구로 차별화 심화.

### Threats (위협)
1. **NetBox 생태계 확장**: 플러그인으로 실측 동기화(napalm 기반) 개선 중 — 폐쇄망 반입 장벽이 낮아지면 강점 잠식.
2. **오픈소스 스캐너 조합**: phpIPAM+Oxidized(config)+LibreNMS 조합이면 기능 다수 재현 가능 — 단 폐쇄망 반입·통합 비용이 방어벽.
3. **장비 OS 변화**: NX-OS/EXOS 명령·출력 형식 변경 시 파서 유지보수 부담 (벤더 자동학습이 완충).
4. **보안 요건 강화**: 감사 도구 자체가 감사 대상 — 단일 토큰·로컬 면제 정책이 조직 보안 심사에서 지적될 수 있음.

## 3. 전략 제언 (우선순위)
1. **[SO] IPAM-lite**: 서브넷 정의 테이블 + 실측 점유율 표시 + 빈 IP 추천. 실측 데이터가 이미 있어 개발비 대비 효과 최대.
2. **[WT] 멀티유저 최소구현**: 열람 전용 토큰 1종 추가(읽기/쓰기 분리)만으로도 보안 심사 방어력 상승.
3. **[W] IPv6 파싱**: 검색·ARP(ND) 수집부터 단계 도입.
4. **[ST] 파서 회귀 픽스처**: 실장비 raw_outputs를 익명화해 테스트 픽스처로 축적 — OS 변화 위협 완충.
